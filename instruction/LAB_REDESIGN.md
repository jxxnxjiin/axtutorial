# Lab 재구성 설계 문서 — 온라인 강의 8강 → 실습 위키 7개 lab

> **목적**: `materials/`에 있는 온라인 강의 8강 분량의 실제 자료를, 현재 `ax-wiki/docs/lab*` 위키의 **구조·톤을 그대로 유지**한 채 7개 lab으로 재구성한다.
> **범위**: 이 문서는 "무엇을 어떤 lab으로, 어떤 step으로" 정하는 **청사진**이다. 실제 md 본문 집필은 이 문서 확정 후 진행한다.
> **작성 근거**: 상위 `README.md`(6유형·5대 사상 이론 노트) + `axtutorial/materials/` 실물 자료 전수 확인.

---

## 0. 결정 사항 (확정)

- **1강(재고자산 워밍업)은 제외한다.** 핵심이던 "표기 통일"은 lab1(모으기)·lab2(뽑기)에 이미 녹아 있어 중복.
- **3강(집계·요약) + 5강(인사이트 도출)은 하나의 lab으로 병합한다.** 집계표가 인사이트의 입력이라 파이프라인이 자연스럽다.
- **2강은 서로 다른 두 유형(모으기 / 뽑기)이므로 lab 2개로 분리한다.**
- 결과: **8강 → 7 lab.**

**페이지 형식 (개정, §2 상세):**

- **단일 코스.** "강사와 함께 가는 최소 코스 / 혼자 더 가는 코스" 분기 폐지 — 모든 참여자가 같은 길로.
- **`extra.md`(＋더 해보기)·`stuck.md`·`못따라왔을때` 완제품 폐지.**
- **소요 시간·"최소 코스"·"오늘 채운 N줄" 누적 문구 전부 제거.** "실습에서 만드는 것" → "**실습에서 할 일**".
- 페이지는 **필요 이상으로 쪼개지 않는다.** 단계로 나눠야 풀리는 문제만 step으로.
- 핵심은 **사용자가 직접 하는 일**(프롬프트 작성·AI에게 시키기·검증)에 대한 **체크리스트(담을 것 ✅ / 뺄 것 ❌) + 체크포인트**. 모범 프롬프트는 **토글**로, 결과는 **실행 예시 이미지**로.

## 2. lab 페이지 형식 표준 (개정판)

기존의 "상황별 가이드"(이렇게 나오면 정상 / 이렇게 나왔다면 …)와 코스 분기·완제품 폴더를 **모두 걷어내고**, **명확한 체크리스트 + 체크포인트** 중심의 간결한 페이지로 간다. 모든 참여자가 **하나의 단일 코스**를 따른다.

### 파일 세트

```
labN/
  index.md      # 시나리오 + 폴더 안내 + "실습에서 할 일"(step 링크)
  step1.md      # 필요한 만큼만. 단계로 나눠야 풀리는 문제일 때만 쪼갠다.
  step2.md      # 불필요하게 잘게 쪼개지 않는다.
```

**폐지 (더 이상 만들지 않음)**: `extra.md`(＋더 해보기), `stuck.md`(막혔을 때), `못따라왔을때/`·`N단계결과/` 완제품 폴더, 그리고 이를 가리키는 모든 문구.

### index.md 구성

1. `# 실습 N · <제목>`
2. **한 줄 목표** (굵게 한 줄). — 예상 소요 시간은 **표기하지 않는다.**
3. `## 오늘 받은 일` — 사수가 시키는 현실 시나리오 인용문.
4. `## 폴더에 있는 것` — 표. **파일명은 `materials/` 안 실제 파일이 원천**(현재 `lab2/` 식 표기는 실제 다운로드 자료와 달라 추후 폴더 구조를 `materials/`에 맞춰 수정 필요).
5. `## 실습에서 할 일` — step 링크 목록. ("실습에서 만드는 것" ❌ → "**할 일**" ⭕). 시간·최소코스·완제품 안내 없음.

**제거된 요소**: `route-badge`(강사 코스/혼자 코스), 예상 소요, "이 실습이 가르치는 한 가지", "내 문장에 이게 있나 / 오늘 채운 N줄" 누적 문구 전부.

### stepN.md 구성 — 사용자가 **직접 하는 일**에 가이드라인 집중

강조점은 **프롬프트 작성 · AI에게 일 시키기 · 결과 검증** 세 가지. 상황별 서술 대신 체크리스트로.

1. `# N단계 · <제목>` + 무엇을 하는 단계인지 1~2줄.
2. **직접 시켜보세요** — 사용자가 자기 문장으로 AI에게 시킨다(짧은 안내 한 줄).
3. `## 프롬프트에 꼭 담을 것` ✅ — "이런 내용이 들어가면 좋아요" 체크리스트.
4. `## 이런 건 빼세요` ❌ — "이런 내용은 안 돼요" 체크리스트.
5. `## 모범 프롬프트` — **토글**(`??? example`) 안에 정답 프롬프트. 먼저 스스로 써본 뒤 열도록.
6. `## 실행 예시` — **실행 결과 예시 이미지** 슬롯. 경로 관례: `![설명](../images/labN/stepM-*.png)`, 실물은 `axtutorial/images/labN/`에 저장(사용자가 별도 준비). 기존 "이렇게 나오면 정상/이렇게 나왔다면" 토글을 **이미지로 대체**.
7. `## 체크포인트` — 체크박스 목록. 이 단계가 끝났는지 사용자가 스스로 확인.

**제거된 요소**: "이렇게 나오면 정상(`!!! success`)/이렇게 나왔다면(`!!! warning`)" 상황 토글, `여러분 문장으로 빈칸`의 장황한 반복, 단계별 소요 시간, "여기서 시간이 다 됐다면 완제품 열기" 안내.

> **유지 원칙**: 대상은 비개발자 신입 사무직(회계·개발 지식 불요). 모든 실습은 **검증(검산)** 으로 끝난다.

## 3. lab별 상세 설계

각 카드: 시나리오 컨셉 · 입력 · step 구성(가안) · 핵심 함정/검산 · 산출물.

> **개정 반영(§2 우선)**: 아래 카드의 `step 구성`은 참고용이며 **필요 이상으로 쪼개지 않는다**. 각 카드의 **`extra:` 항목은 별도 페이지가 아니라**, 해당 실습 마지막 단계에 녹이거나 생략한다(＋더 해보기 페이지 폐지). 소요 시간·최소코스 표기 없음.

### lab1 — 흩어진 주문 한 표로 모으기 (2강-A · ② 모으기)

- **시나리오**: 영업지원 신입. "웹·전화·제휴 세 경로로 들어온 주문을 하나의 주문대장으로 합쳐줘. 근데 세 파일 양식이 다 달라."
- **입력** (`materials/2강/1. Order/`):
  - `웹주문.xlsx`(150건, 한글 헤더), `전화주문.xlsx`(140건, 영문 헤더 `order_id/name/...`), `제휴주문.xlsx`(120건, `협력사주문ID/구매자/...`)
  - `작업방법참고.xlsx` — 표준 7칸 규칙 + 열 매핑 대조표(종합↔웹↔전화↔제휴)
  - `주문종합.xlsx` — 빈 템플릿(헤더만): `주문번호·고객명·상품명·수량·금액_원·주문일·주문채널`
- **step 구성(가안)**:
  1. 세 파일 열어 **같은 뜻 다른 이름** 찾기(`금액=amount=결제액`)
  2. 표준 7칸 매핑 규칙 주고 통합 실행
  3. 검산 — 행 수 대조 + `출처채널` 기록 + 날짜 `YYYY-MM-DD` 통일
- **핵심 함정/검산** (README ②):
  - 모으기를 줄이기와 혼동(합계 내지 말 것 — 행 보존)
  - **빈칸 ≠ 0** / 같은 주문번호 중복 제거(먼저 등장 채널 기준)
  - 검산: `통합행수 = 웹+전화+제휴 − 중복제거건수`
- **산출물**: 채워진 `주문종합.xlsx`
- **extra**: 새 채널 파일 하나 더 추가해도 규칙 그대로 → lab7(재사용) 복선

### lab2 — 계약서 더미에서 계약대장 뽑기 (2강-B · ① 뽑기)

- **시나리오**: 총무 신입. "계약서 PDF 8건에서 계약번호·기간·금액·자동갱신 여부를 뽑아 대장으로 만들어줘."
- **입력** (`materials/2강/2. contract/`): `CT-2026-001.pdf` ~ `CT-2026-008.pdf` (표준계약서 양식)
- **step 구성(가안)**:
  1. 계약서 1건으로 **뽑을 필드 정의**(계약번호·상대·목적·계약기간·계약금액·지급조건·갱신)
  2. 8건 일괄 → 계약대장 표
  3. 검산 — **지어내기 금지**(금액 조항 없으면 빈칸) + **표기 통일**(`2026년 8월 7일`↔`2026.08.07`, `KRW 9,000,000`↔`9000000`)
- **핵심 함정/검산** (README ①):
  - 없는 값 환각 채우기 → "안 적힌 항목은 빈칸, 지어내지 말 것" 못 박기
  - 한두 건 원본 대조 검산
- **산출물**: 계약대장(계약번호·상대·기간·금액·갱신여부…)
- **extra**: 만료 임박(예: 90일 내) 계약만 필터 → ⑥ 검사 맛보기 / 스캔·영문 PDF 대응

### lab3 — 쿠폰 성과 집계하고 인사이트 뽑기 (3강+5강 · ③ 줄이기 + 분석) ★병합

- **시나리오**: 마케팅 신입. "5개 채널 주문로그 9천 줄에서 쿠폰별 성과를 뽑고, **그래서 뭐가 문제인지** 인사이트까지 정리해줘."
- **입력** (`materials/3강/`):
  - 채널별 `1~5.주문기록_*.xlsx`(각 ~1,900행) + `6.GA5_주문종합.xlsx`(9,390행, `판매채널` 포함)
  - `7.쿠폰별성과표.xlsx` — **빈 템플릿**(44 쿠폰 행, 헤더: 매출합계·할인합계·매출이익·순이익·매출순이익률·사용건수·적자여부)
  - (5강 폴더의 `7.쿠폰별성과표.xlsx`는 **완성본** — 정답/못따라왔을때 자료로 활용)
- **step 구성(가안)** — 앞 3 step = 집계(3강), 뒤 2 step = 인사이트(5강):
  1. 원본 훑고 **조인 개념** 잡기(쿠폰기록 ↔ 주문기록을 쿠폰코드로 연결)
  2. 쿠폰코드로 조인 후 쿠폰별 집계 → 빈 성과표 채우기
  3. 집계 검산(결제완료만 필터 / 가중 vs 단순평균 / 사용건수=행수)
  4. **인사이트 도출** — 적자 쿠폰·상위 쿠폰·채널 편차를 숫자 근거와 함께
  5. 인사이트 검산 — 문장마다 "이 숫자 어느 셀에서 나왔나" 자수시키기
- **핵심 함정/검산** — **이 lab의 하이라이트, 두 층**:
  - *집계 층(README ③)*: ① 조인 먼저(안 맞추면 A쿠폰 실적이 B로) ② 결제완료만(취소 넣으면 적자→흑자 둔갑) ③ 전체 ROI=`총순이익÷총할인`(가중), 단순평균 금지
  - *인사이트 층(5강 고유)*: ① **근거 없는 해석 환각 금지**("MZ에 인기라서" 같은 데이터에 없는 인과) → 인사이트는 숫자에 묶고 "왜"는 데이터로만 ② **과장 형용사 금지**("압도적" → "순이익률 20%p 차") ③ 검산: "총 사용건수 = 결제완료 행 수?"
- **산출물**: 채워진 `쿠폰별성과표.xlsx` + 인사이트 메모(→ lab5 보고서 입력)
- **extra**: 채널별·월별로 더 쪼개 보기

### lab4 — 고객 문의 520건에 딱지 붙이기 (4강 · ④ 분류)

- **시나리오**: CS 신입. "고객 문의 520건을 문의유형·감정·위험대응 3가지로 분류해줘. 기준 문서 줄게."
- **입력** (`materials/4강/`):
  - `1. VOC원문.xlsx`(520건: item_id·채널·text)
  - `2. VOC_분류기준.pdf` — 3축 기준(문의유형 6종·감정 3종·위험 Y/N) + 복합·경계 규칙
  - `3. 분류표.xlsx` — 빈 템플릿(item_id·채널·문의유형·감성·위험대응)
- **step 구성(가안)**:
  1. 기준 PDF 읽히고 VOC 1건 분류해 보기
  2. **3축 독립** 규칙 못 박기(감정 긍정이어도 위험신호 있으면 Y)
  3. 520건 일괄 분류
  4. 전수 검산 — 보기 밖 값·빈칸 있는 줄 전부 신고 + 경계 케이스 되묻기
- **핵심 함정/검산** (README ④):
  - 느낌으로 찍기 → "어떤 말이 들어 있나"로 규칙화
  - 축 넘겨짚기(기분≠위험) / 빈칸을 추측으로 메우기(→ 기타·중립·보류)
  - 흔한 쪽으로 몰기(드문 칭찬감사·기타 놓침)
- **산출물**: 채워진 `분류표.xlsx`
- **extra**: 분류 결과로 담당 부서 라우팅 / 위험 Y 건만 추출

### lab5 — 임원용 1페이지 보고서 쓰기 (6강 · ⑤ 쓰기)

- **시나리오**: "쿠폰 성과 분석했지? 이제 대표님께 올릴 1페이지 보고서로 만들어줘. 대표님 성향 메모랑 양식 줄게."
- **입력** (`materials/6강/`):

  - `8.보고대상_프로필.md` — 대표이사 스타일(숫자·결론 먼저, 1페이지, 형용사 싫어함, 출처 필수, 건의 필수)

  - 환각(자료에 없는 "업계 1위") → 문장마다 `(근거: 파일·시트)` 꼬리표

  - 산문 품질은 사람이 다듬되 **사실은 AI가 못 지어내게**
- **산출물**: 1페이지 보고서.md (lab3 인사이트를 받는 하류)

### lab6 — 부풀려진 제안서 사실로 되돌리기 (7강 · ⑤ 쓰기 + ⑥ 검사)

- **시나리오**: 영업 신입. "선배가 쓴 제안서 초안인데, 과장이 좀 있는 것 같아. 사양서랑 고객 요구랑 맞는지 보고 사실대로 고쳐줘."
- **입력** (`materials/7강/`):
  - `1.영업제안서_초안.pdf` — 과장·불일치 심긴 초안("시장점유율 1위" 환각, 제안모델 HC-12지만…)
  - `2.제품사양서.xlsx` — 실제 사양(HC-08만 존재, 가반하중·가격·유지비)
  - `3.고객사_요구사항.pdf` — 미팅메모(가반하중 10kg↑, 야간 무인, 라인 연동, 1.2억 이내, 3개월 내 설치, KCs 인증 6개 조건)

  1. 초안을 사양서·요구사항과 **대조**하며 읽기
  2. **불일치·환각 잡기**(근거 없는 최상급 / 사양서에 없는 모델·수치)

  4. 요구사항 6개 **충족 여부 검사표**로 마무리
- **핵심 함정/검산** (README ⑤+⑥):

- **산출물**: 교정 제안서 + 요구사항 충족 검사표
- **extra**: 고객 반론 예상 Q&A / 다른 모델로 재제안

### lab7 — 반복작업을 재사용 스킬로 남기기 (8강 · 재사용·확장)

- **시나리오**: "지난번 주문 합치기, 이번 달 또 해야 해. 그리고 옆 팀은 견적서를 합치고 싶대. 매번 새로 시키지 말고 도구로 만들자."
- **입력** (`materials/8강/`):
  - `1.주문통합/`(웹.xlsx·전화.**csv**·제휴.xlsx + `주문통합_작업지침.md`)
  - `2.견적통합/`(거래처 3곳 견적, 열 이름 제각각 + csv/xlsx 혼재)
  - `3.스킬예시/SKILL.md` — 완성된 재사용 스킬 예시(데이터통합)
- **step 구성(가안)**:
  1. lab1에서 한 통합을 **다시** — 두 번째는 지시가 거의 한 줄
  2. 규칙을 `SKILL.md`로 고정(파일명·열이름 하드코딩 금지)
  3. **견적 통합으로 변형** — 재료만 바꿔 같은 스킬 동작(csv+xlsx 혼재, 다른 열이름)
  4. 동료에게 넘기기(폴더째 전달) — 내 도구가 팀 도구로
- **핵심 함정/검산** (README 사상3):
  - 매번 다른 건 **데이터**지 **절차**가 아니다
  - 스킬은 특정 파일명에 묶지 말 것(범용 매핑) + 통합 검산 내장
- **산출물**: 동작하는 `SKILL.md` + 두 종류(주문·견적) 통합 결과
- **extra**: 세 번째 유형으로 확장(예: 재고 파일 통합)

## 6. build_wiki.py / 네비게이션 반영

lab을 재구성하면 `axtutorial/build_wiki.py`의 `NAV`와 다운로드 섹션도 함께 손봐야 한다.

- **`NAV`**: 현행 lab1~4(+삭제된 lab5/6) 항목을 신규 7개 lab 구조로 교체(섹션 제목·step 라벨·경로).
- **`FLAT`/사이드바/이전-다음**: `NAV`에서 자동 생성되므로 `NAV`만 정확히 고치면 됨.
- **`index.html` 본문**: "오늘의 지도" WORK 01~04 카드와 "강의 자료 내려받기"(`#materials`)는 **수동 편집 대상** — 새 7개 lab에 맞게 직접 수정.
- **stale 정리**: 옛 lab의 `.html`은 `python3 build_wiki.py --prune`으로 삭제(연결 끊긴 페이지 자동 제거).
- **다운로드 zip**: `materials/zips/N강.zip`을 lab 기준으로 다시 매핑(2강 zip은 lab1·lab2 둘로 나뉨; 3강·5강 zip은 lab3 하나로).
