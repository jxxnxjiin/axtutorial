# 1단계 · 작업지침을 범용 스킬로 만들기

이 단계는 세 토막입니다. **지침 고치기 → 고친 지침으로 돌려보기 → 스킬로 굳히기.** 하나씩 갑니다.

## ① 박혀 있는 지침을 범용으로 고치기

먼저 주문통합 폴더의 작업지침 파일을 열어 보세요. 지난달에 세 채널 주문을 합치려고 만들어 둔 지침으로, 표준 7칸·날짜 통일·빈칸 유지·행 수 검산까지 규칙 자체는 아주 잘 만들어져 있습니다.

그런데 `웹주문.xlsx`, `order_id`, `협력사주문ID`… 파일명과 열 이름이 그대로 박혀 있어 딱 이 세 파일 전용입니다. 다음 달에 파일 이름이 바뀌면 다시 손봐야 하고, 동료에게 넘기기도 어렵습니다.

고치는 방향은 하나입니다. "파일명을 고정" 대신 **"내용을 보고 표준 칸에 맞춘다"**로 바꾸면 재료가 무엇이든 통합니다. 이 범용화를 여러분이 직접 고쳐 쓰는 게 아니라 **AI에게 시킵니다.**

### 프롬프트에 꼭 담을 것 ✅

- [ ] **고칠 대상** — 지금 있는 작업지침을 재사용 가능한 범용 규칙으로 다시 쓰기
- [ ] **박힌 이름 제거** — 특정 파일명·열 이름을 미리 정해 두지 말고, 각 열의 **뜻**을 보고 표준 칸에 연결하도록 (이름이 박혀 있으면 그 파일 전용이 됩니다)
- [ ] **기존 규칙 유지** — 표준 7칸·날짜 형식·빈칸 유지·행 수 검산은 그대로
- [ ] **중복은 조건부로** — 고유키(예: 주문번호)가 있을 때만 중복 제거, 그런 키가 없으면 모든 행을 남기도록
- [ ] **애매하면 질문** — 뜻이 불분명한 열은 넘겨짚지 말고 나에게 되묻게 (열 하나 잘못 짝지으면 결과가 통째로 틀립니다)

### 이런 건 빼세요 ❌

- [ ] `웹주문.xlsx`·`전화주문.csv` 같은 **파일명을 규칙에 그대로 남기기** (다음 달에 못 씀)
- [ ] "알아서 범용으로 해줘"처럼 **범용의 기준 없는 지시**
- [ ] 중복 제거를 **항상 켜 두기** (키가 없는 데이터에서는 멀쩡한 행을 지웁니다 — 2단계에서 문제됨)

??? example "이렇게 시킬 수 있습니다"
    ```
    이 @lab7/1.주문통합/주문통합_작업지침.md 는 지금 특정 파일명과 특정 열 이름에 맞춰져 있어. 이걸 어떤 파일이 와도 쓸 수 있도록 범용 절차로 다시 써줘.
    - 파일명을 고정하지 말고 '폴더 안의 표 파일을 전부 찾는다'로, 열 이름도 고정하지 말고 '각 열이 주문번호인지·고객명인지·금액인지 내용을 보고 표준 칸에 맞춘다'로 바꿔줘.
    - 표준 7칸(주문번호·고객명·상품명·수량·금액_원·주문일·출처채널), 날짜 `YYYY-MM-DD`, 금액 콤마 제거, 빈칸은 비워두기, 행 수 검산 — 이 규칙은 그대로 유지해.
    - 중복 제거는 주문번호 같은 고유키가 있을 때만 하고, 없으면 모든 행을 남기도록 조건을 달아줘.
    - 열 이름이 애매해서 어느 칸에 넣을지 모르겠으면 지어내지 말고 나한테 물어봐.
    ```

고쳐진 지침을 열어 보면 아까보다 단계가 나뉘고 훨씬 세세해졌을 겁니다. 마지막에 "모르면 물어보고 실행"이라는 규칙이 붙은 것도 확인해 보세요.

## ② 고친 지침으로 실제 통합해 보기

지침이 세세해졌으니 이제 시키는 말은 짧아도 됩니다. 규칙을 다시 설명하지 않고 지침만 가리킵니다.

??? example "이렇게 시킬 수 있습니다"
    ```
    방금 고친 lab7/1.주문통합/주문통합_작업지침.md 를 따라서 1.주문통합 폴더의 주문 파일들을 하나로 합쳐줘.
    결과는 같은 폴더에 주문통합_결과.xlsx 로 저장하고, 행 수 검산표를 같이 보여줘.
    ```

`주문통합_결과.xlsx`가 새로 만들어지고, 행 수 검산(3파일 합 − 중복 제거 = 통합 행 수)이 맞으면 범용화 성공입니다. 완성 예시는 예시답안 폴더의 `lab7/주문통합_결과.xlsx`와 비교해 볼 수 있습니다.

## ③ 이 절차를 스킬로 굳히기

지금부터가 이 실습의 핵심입니다. 방금 검증된 범용 지침을 따라 일하는 절차에 **이름을 붙여 도구로 저장**합니다. Claude Code에서는 이것을 **스킬**이라고 부릅니다.

!!! info "스킬이 뭐고, 어떻게 동작하나요?"
    스킬의 실체는 코드가 아니라 **폴더 하나에 든 `SKILL.md` 글 파일 하나**입니다. 파일은 두 부분으로 되어 있습니다.

    - **맨 위 몇 줄** — 스킬의 이름과 "언제 쓰는 도구인지" 한 줄 설명
    - **그 아래 본문** — 실제로 따를 절차 (여러분이 방금 만든 범용 지침 같은 것)

    동작 방식이 재밌습니다. AI는 대화를 시작할 때 스킬들의 **이름과 설명만** 훑어 둡니다. 그러다 관련된 일이 들어오면 — "파일 여러 개를 합쳐줘" 같은 — 그제서야 해당 스킬의 본문을 펼쳐 읽고 그 절차대로 일합니다. 매번 지침을 다시 설명할 필요가 없는 이유입니다. 알아서 꺼내 쓰기를 기다리지 않고 `/스킬이름`으로 직접 켤 수도 있습니다.

    같은 대화창에 붙여넣는 것과 뭐가 다르냐면, 붙여넣기는 그 대화에서만 유효하지만 스킬은 **파일로 남아 다음 대화에서도, 다른 폴더에서도, 동료의 컴퓨터에서도** 쓸 수 있다는 점입니다. 반복해서 설명하게 되는 절차가 있다면 그게 스킬로 만들 신호입니다.

??? example "이렇게 시킬 수 있습니다"
    ```
    /skill-creator:skill-creator  방금 검증한 범용 통합 절차를 데이터통합이라는 이름의 스킬로 만들어줘.
    현재 폴더의 .claude 폴더 하위에 저장해줘.
    ```

잠시 기다리면 `.claude`라는 폴더가 생기고, 그 안 `skills/데이터통합/SKILL.md`에 지금까지 이야기한 규칙이 전부 담겨 있을 겁니다. 이제 채팅창에서 이름만 부르면 자동으로 불러와지는 도구가 된 것입니다. 절차가 머릿속이 아니라 파일로 남는 순간입니다.

`3.스킬예시/SKILL.md`가 이렇게 만들어진 스킬의 완성 예시입니다. 내 스킬과 비교해 보세요.

## 체크포인트

- [ ] 작업지침이 **특정 파일명·열 이름 없이** 범용 규칙으로 다시 써졌다
- [ ] 지침에 **애매하면 되묻기**·**조건부 중복 제거**·**검산** 규칙이 들어 있다
- [ ] 고친 지침으로 통합한 `주문통합_결과.xlsx`의 **행 수가 검산과 맞는다** (3파일 합 − 중복 제거 = 통합 행 수)
- [ ] `.claude/skills/데이터통합/SKILL.md`에 스킬이 **실제로 저장**됐다
