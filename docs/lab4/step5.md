# 5. 스킬로 두 가지 무드 비교하기

!!! abstract "이 단계에서 하는 일 (약 15분)"
    - 지금 화면을 **복사해서** 두 벌을 만듭니다
    - 각각에 다른 도구를 적용해 인상을 갈아입힙니다
    - 두 창을 나란히 놓고 하나를 고릅니다

이 파트의 절정입니다. **같은 데이터, 다른 인상**을 눈으로 봅니다.

---

## 원본을 복사해서 각각에 적용합니다

스킬 이름은 철자를 틀리면 안 되는 값이라 그대로 드립니다. **복사해서 쓰세요.**

!!! quote "첫 번째 벌"
    ```
    지금 화면을 dashboard_A.html로 복사한 다음, 그 복사본에 /minimalist-ui 를 적용해줘.
    숫자와 표 내용은 바꾸지 말고 보이는 모양만 바꿔줘.
    ```

!!! quote "두 번째 벌"
    ```
    이번엔 원본을 dashboard_B.html로 복사하고, 그 복사본에 /industrial-brutalist-ui 를 적용해줘. 조건은 같아.
    ```

**원본을 복사해서 각각에 적용하는 게 핵심입니다.** 나란히 비교하려면 파일이 두 개여야 하고, 원본이 남아 있어야 되돌릴 수 있습니다.

---

## 고를 수 있는 도구 네 개

두 개를 골라 쓰세요.

| 이름 | 어떤 느낌 | 어울리는 경우 |
|---|---|---|
| `/minimalist-ui` | 잡지 같은 편집 느낌. 흰 여백이 많고 색은 절제 | **기본 추천.** 대부분의 업무 화면에 안전하게 어울림 |
| `/industrial-brutalist-ui` | 설계도·관제실 느낌. 굵은 격자와 극단적인 글자 크기 대비 | 변화가 가장 극적. 취향이 갈림 |
| `/high-end-visual-design` | 값비싼 브랜드 사이트 느낌. 그림자·간격·움직임까지 | 인상이 가장 셈. 시간이 조금 더 걸림 |
| `/redesign-existing-projects` | 지금 화면을 **안 깨뜨리고** 고급스럽게 | **안전 선택.** 기능이 살아 있어야 할 때 |

!!! warning "스킬 이름이 인식되지 않는다면"
    `lab4/디자인_지시문/` 폴더에 대체 파일 3장이 들어 있습니다. 결과 품질이 거의 같습니다.

    ```
    디자인_지시문/편집형_잡지느낌.md를 읽고 그 규칙대로 이 화면을 다시 만들어줘.
    숫자와 표 내용은 바꾸지 마.
    ```

    | 파일 | 대신하는 것 |
    |---|---|
    | `편집형_잡지느낌.md` | `/minimalist-ui` |
    | `관제실_설계도느낌.md` | `/industrial-brutalist-ui` |
    | `고급스러운_느낌.md` | `/high-end-visual-design` |

---

## 두 창을 나란히 놓고 봅니다 (3분)

`dashboard_A.html` 과 `dashboard_B.html` 을 각각 더블클릭해 **창 두 개를 나란히** 띄우세요.

!!! example "세 가지만 물어보세요"
    - 제일 먼저 눈에 들어오는 게 뭐예요?
    - **급한 계약이 급해 보여요?**
    - 팀장님한테 보낸다면 어느 쪽?

**둘 다 괜찮아서 못 고르겠다면** 기준은 하나입니다.

> **이 화면을 보는 사람이 30초 안에 뭘 해야 하는지 알 수 있는 쪽.**

예쁜 쪽이 아니라 **급한 게 급해 보이는 쪽**입니다.

---

## 뭐가 달라졌는지 봅니다

!!! success "이렇게 나오면 정상입니다"
    - `dashboard_A.html` 과 `dashboard_B.html` 이 둘 다 있습니다
    - 원본 `dashboard.html` 도 그대로 있습니다
    - 두 화면의 인상이 확실히 다릅니다
    - **두 화면의 표 행 수가 서로 같고, 엑셀과도 같습니다**

!!! warning "이렇게 나왔다면"
    - 원본이 덮였다 → **"원본 dashboard.html을 디자인 적용 전 상태로 되돌려줘"**
    - 한쪽 표가 짧아졌다 → **"이 화면의 표 행 수를 세서 알려주고, 빠진 행이 있으면 다시 넣어줘"**
    - 스킬이 실행은 됐는데 화면이 안 열린다 → **"화면이 안 열려. 지금 뭘 해야 볼 수 있는지 순서대로 알려줘"**
    - 시간이 빠듯하다 → 한 벌만 만들어도 됩니다. **하나라도 갈아입혀 보는 것이 이 단계의 목적**입니다

??? note "스킬이 담고 있는 게 뭔가요"
    취향이 아니라 **금지 목록**입니다. "기본 글꼴 쓰지 마라, 기본 그림자 쓰지 마라" 같은 것들이요.

    궁금하면 `디자인_지시문/` 의 md 파일 하나를 열어보세요. 인상의 마지막 차이를 만드는 게 뭔지 20초면 보입니다.
