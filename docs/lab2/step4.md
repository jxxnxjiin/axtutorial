# 4단계. 인터넷 공고 가져와 나누기

!!! abstract "이 단계에서 하는 일 (약 18분)"
    - 인터넷에 올라온 입찰 공고를 지금 가져옵니다 (4분)
    - 내가 쓴 회사소개를 기준으로 우리 일인지 나눕니다 (14분)
    - 애매한 건을 애매한 채로 남깁니다

여기가 이 실습의 본체입니다. 그리고 **다섯 줄이 완성되는 자리**입니다.

!!! info "이 단계의 결과 파일 이름과 칸 규격은 이 페이지 맨 아래에 있습니다"

## (1) 수집 — 4분

주소는 철자를 틀리면 안 되는 값이라 그대로 드립니다. **여기는 조립할 것이 없습니다.**

!!! quote "그대로 복사해서 쓰세요"
    ```
    아래 RSS 주소에서 공고를 15건 이상 가져와서 공고명·게시일·링크를 표로 정리해줘.
    ```

    - <PLACEHOLDER_RSS_A>
    - <PLACEHOLDER_RSS_B>

!!! success "이렇게 나오면 정상입니다"
    공고명·게시일·링크가 있는 표가 15행 이상 화면에 나옵니다. 링크를 눌러보면 실제 공고 페이지가 열립니다

!!! warning "인터넷이 막혔거나 주소가 응답하지 않는다면"
    `lab2/공고_백업/` 을 씁니다. 실습은 그대로 진행됩니다.

    1. `서버켜기.bat` (맥은 `서버켜기.command`) 를 더블클릭합니다. 검은 창이 열린 채로 두세요
    2. 브라우저에서 `http://localhost:8099/rss_A_교육기관.xml` 이 열리는지 확인합니다
    3. 위 문장의 주소 자리에 아래 두 개를 대신 넣습니다
        - `http://localhost:8099/rss_A_교육기관.xml`
        - `http://localhost:8099/rss_B_지자체.xml`

    검은 창이 안 열리면 `공고_백업/백업_사용법.txt` 의 4번을 보세요.

### 나온 것을 열어봅니다

!!! example "세 가지를 세어보세요"
    - **보류가 몇 건인가요?**
    - **옆자리의 `가능` 건수와 비교해보세요.** 회사소개가 다른데 결과가 비슷하지 않나요?
    - 가장 애매했던 것 하나를 고르세요. **그게 왜 그 판정이에요? 공고 본문 어디에 그렇게 적혀 있어요?**

    세 번째 질문에 답을 못 하면, 그게 지금 상태의 진단입니다.

---

??? question "① 5분이 지나도 막혔다면 — 아직 펼치지 마세요"
    지금 결과에 `판단보류` 가 몇 건인가요? 애매한 게 정말 하나도 없었을까요?

??? tip "② 9분이 지났다면 — 정해야 할 세 가지"
    정해야 할 것은 셋입니다 — **애매한 건을 어떻게 둘지 / 무엇을 읽고 판단하게 할지(제목인지 본문인지) / 그걸 어떻게 표시에 남길지.**

    쓸 수 있는 라벨은 `가능` · `불가` · `판단보류` 셋뿐이고, `판단방식` 칸은 `읽고판단` · `단어대조` 둘 중 하나입니다.

    이 단계 결과는 `다음달_챙길일.xlsx` 의 `신규공고` 시트에 들어갑니다.

??? example "③ 모범답안 — 잘 되는 문장은 이렇게 생겼습니다 (여러분 문장을 한 번 보내본 뒤에 여세요)"

    ```
    내가 쓴 회사소개.md를 먼저 읽고, 위 공고들을 가능·불가·판단보류로 나눠줘.
    제목의 단어로 맞추지 말고 공고 본문 링크를 열어서 읽고 판단해줘.
    애매하면 억지로 고르지 말고 판단보류로 두고, 뭐가 애매한지 한 줄로 적어줘.
    각 건마다 본문을 읽고 판단했는지 제목 단어로 맞췄는지 판단방식 칸에 표시해줘.
    결과는 다음달_챙길일.xlsx의 신규공고 시트에 저장해줘.
    ```

    **이 문장이 하는 일**

    | 이 줄이 | 없으면 |
    |---|---|
    | `내가 쓴 회사소개.md를 먼저 읽고` | 방금 만든 파일이라 **말하지 않으면 존재를 모릅니다.** 일반적인 기준으로 나뉘어 옆자리와 결과가 같아집니다 |
    | `본문 링크를 열어서 읽고` | 제목만 보고 나눕니다. 제목이 애매한 건이 한쪽으로 쓸려 들어가고 **그게 일어났다는 것조차 안 보입니다** |
    | `애매하면 판단보류로 두고 뭐가 애매한지` | 전부 깔끔하게 둘로 갈립니다. 보류 0건은 잘한 게 아니라 **누군가 대신 정한 것**입니다 |
    | `판단방식 칸에 표시해줘` | 본문을 읽었는지 제목만 봤는지 확인할 방법이 없습니다. 이 칸이 있어야 눈으로 셀 수 있습니다 |

    **한 번에 잘 됐다면** — 여러분 문장에 **"애매하면"** 줄이 있었는지 보세요.
    **아직 어긋난다면** — 이 문장으로 갈아타고 검산으로 가세요. 보류 건이 생겼는지만 확인하면 됩니다. **오늘은 완주가 먼저입니다.**

## 검산 — 다섯 가지

1. 브라우저에서 RSS 주소를 직접 열어 **항목 수를 세고** 결과 행 수와 비교합니다
2. **링크 3개를 눌러** 실제 공고 페이지가 열리는지 확인합니다
3. `가능` 으로 나온 것 5건을 직접 읽고, 내가 쓴 회사소개와 맞는지 봅니다
4. **`단어대조` 로 표시된 건이 몇 개인가요?** 많으면 고쳐 말하기를 한 번 더 합니다
5. `판단보류` 로 남긴 것 중 하나를 골라, **내가 뭘 몰라서 보류했는지** 한 줄로 적습니다

## 뭐가 달라졌는지 봅니다

!!! success "이렇게 나오면 정상입니다"
    - `다음달_챙길일.xlsx` 에 `신규공고` 시트가 생겼습니다 (백업 자료로 했다면 **20행**, 라이브로 가져왔다면 가져온 건수만큼)
    - 라벨이 `가능` · `불가` · `판단보류` 셋 안에만 있습니다
    - **`판단보류` 가 한 건 이상 있습니다**
    - `판단방식` 칸에 `읽고판단` 이 대부분입니다
    - 링크를 눌렀을 때 실제 공고 페이지가 열립니다

!!! warning "이렇게 나왔다면"
    - **보류가 0건이다** → **"제목만으로는 우리 일인지 애매한 공고가 몇 건인지 세고, 그 건들의 본문에서 애매한 부분을 인용해줘"**
    - `판단방식` 이 전부 `단어대조` 다 → **"각 공고의 본문 링크를 실제로 열어서 다시 판단하고, 판정이 바뀐 건만 알려줘"**
    - 옆자리와 결과가 거의 같다 → 회사소개를 안 읽힌 것입니다. **"내가 쓴 회사소개.md를 읽고, 그 문서의 어느 줄을 근거로 이 판정을 했는지 건마다 적어줘"**
    - 링크가 안 열린다 → 백업 자료로 전환하세요. 위 (1)의 경고 상자를 보세요
    - 라벨이 `검토필요` 같은 다른 말이다 → **"라벨을 가능·불가·판단보류 셋 안에서만 쓰도록 고쳐줘"**

??? note "왜 '애매하면 어떻게 하라'를 같이 말해야 할까요"
    숫자를 더하고 표를 합치는 일은 규칙으로 처리하는 게 빠르고 정확합니다. 그런데 **'이게 우리가 할 만한 일인가' 같은 판단은 규칙으로 접으면 망가집니다** — 돌려 말한 문장, 예외적인 조건이 규칙 밖으로 새어나가기 때문입니다.

    계산은 규칙으로, **판단은 직접 읽게** 나눠서 시킵니다. 그리고 애매한 것은 애매한 채로 남기라고 말해야 남습니다.

## 이 단계 결과물 규격

`다음달_챙길일.xlsx`

| 시트 | 칸 이름 (이 순서, 이 표기) | 행 수 |
|---|---|---|
| `신규공고` | 공고명 / 게시일 / 링크 / 판정 / 이유 / 판단방식 | 가져온 공고 건수 (백업 자료 기준 20) |

**값 표기 규칙**

| 칸 | 규칙 |
|---|---|
| 게시일 | `2026-09-30` 한 가지 형태 |
| `판정` | `가능` / `불가` / `판단보류` — 이 셋 밖의 표현 금지 |
| `판단방식` | `읽고판단` / `단어대조` 둘 중 하나 |
| `이유` | 판정 근거를 한 줄로. `판단보류` 는 **뭐가 애매한지**를 적습니다 |
